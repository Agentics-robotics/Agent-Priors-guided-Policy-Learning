# Policy implementation requirements

These requirements complement the short Stage 2 prompt. They apply to prior planning and to every model implementation.

- Keep the cut's responsibility, supervised segments and substantial overlap. Each skill-prior pair has its own model and weights. Plan and implement the priors together so that their expected failures differ. Submit the full set for a skill before formal training; retain edits and bounded check diagnostics for unsubmitted packages.
- For each model, name its generalization objective, useful invariant or predictable transformation, retained robot/world/contact dependencies and falsifiable benefit. Connect the proposed mechanism to actual implementation functions. Relative coordinates alone do not make the entire control problem ID.
- HL supplies intent through typed arguments; the executor supplies real physical observations. Resolve a referenced object's current pose at each replan unless a fixed spatial goal is explicitly intended. Distinguish target, destination and possibly held/previous object. Arguments must actually enter the declared computation.
- Use the same build_inputs and argument interpretation in training and deployment. Bind every occurrence, including overlaps. Keep the two causal frames across policy switches and document initial padding. Futures, unprovided action history and simulator contact truth are not inference inputs.
- Keep substantial overlap in action supervision, not only as observation context. Document indices, masks and parameter meaning; report conflicting supervision rather than silently trimming it. Different prior implementations do not choose new cuts based on performance.
- encode_targets and decode_action must agree on dimensions, units, frames, action alignment and chunk-start/current-step references. Explain accumulation for increments. Convert every end-effector output to native joint targets with the supplied panda_kinematics.solve_ik from the measured joints; state the frames and orientation representation, and report the solver diagnostics. Preserve the native gripper semantics.
- Check numerical roundtrip consistency for invertible conversions. For nonunique IK, check the declared independent task-space consistency and feasibility. Record conversion residuals. These checks do not establish manipulation success.
- Fit normalization only on authorized training data and in the coordinates actually used. Handle constant/narrow channels. Augmentation must preserve or recompute valid labels, causal information and physical feasibility.
- Learned encoders, gates and heads must be registered model modules included in the optimizer and checkpoint/EMA. Auxiliary losses require valid targets, masks and a real gradient path into the intended learned modules. Report diffusion and auxiliary terms separately and explain weights. Keep action diffusion learning active; predicting an auxiliary label cannot replace it.
- Auxiliary heads are optional; no artificial loss is required for a useful representation or architecture prior. Predictions from causal observations may be used at deployment if declared. Ground-truth future or privileged training targets may not be substituted for these predictions. Do not advance physical history or phase memory on repeated denoising forward calls. No new generic recurrent state interface is introduced.
- Preserve flexible input shapes, typed arguments, variable learned output dimension and the 64M parameter ceiling. Prefer keeping the standard DP backbone unchanged and explain necessary changes. The H2/16/8 and 20 Hz configuration remains fixed.
- PRIOR.md states the mechanism, support and limitations. HANDOFF.json states entry_conditions, exit_conditions, overlap_role, successor_readiness, failure_signatures and continuation_guidance, with inspected evidence. These are guidance for HL, not additional task-success requirements. A closed gripper or predicted stage alone does not establish a grasp.
- Use the interface's exact policy/adapters/contract/binding/pipeline schemas. Run only the declared bounded checks for shapes, causality, masks, gradients, action conversion, sampling and reload. No design-stage task rollouts or final-test feedback. Submitted packages and formal last-EMA selection remain immutable.
